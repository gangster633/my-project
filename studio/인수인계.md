# AI 영상 공방 인수인계

마지막 정리: 2026-11-23 · 프로그램 버전 1.3.15

이 문서는 "AI 영상 공방" 프로그램과 이 프로그램으로 운영 중인 유튜브 채널 작업을 이어받는 사람(또는 다음 Claude 세션)을 위한 정리입니다.

## 2. 사용자 현재 상황 (2026-11-23 기준)

### 유튜브 채널
- 채널 이름: **세상사는 이야기**, 핸들 **@세상사는이야기**, 40대 이상 시청자
- 방향이 바뀜: "매일 보지만 몰랐던 우리 주변 이야기" → **"몰라서 손해 보는 생활 속 돈 이야기"** (조회수 조사 결과에 따라)
- 목표: 새 채널이라 **영상당 조회수 1만 회**를 현실적인 첫 목표로 둠
- 영상 현황

| # | 영상 | 상태 |
|---|---|---|
| 1 | 동네 목욕탕이 사라지는 이유 (약 18분) | 올림. 조회수 매우 적음 |
| 2 | 요양보호사가 그만두는 핵심적인 이유 (약 20분) | 업로드 정보까지 만듦 |
| 3 | **출근할 때 보일러 '이 버튼' 누르지 마세요** (난방비, 약 15분, 27컷, 웹툰) | 영상 완성. 흔들림 문제로 1.3.7 이후 다시 만들고 재업로드를 권함 |
| 4 | **고향사랑기부제 2026, 올해는 10만 원 말고 20만 원 하세요** (약 15분, 36컷, 웹툰, 1인칭 "저와 우리 부모님" 시점) | 음성 다시 만듦(끊어 읽기 반영). 영상·쇼츠 다시 만들고 올릴 차례. 쇼츠 구간 문장 67~75 |

- 같은 주인공을 두 영상에 씀: "a Korean woman in her mid-40s with shoulder-length black hair in a low ponytail, wearing a beige knit cardigan over a light gray top and dark blue jeans" (부모님은 70대 부부)
- 채널에 예전 다른 주제 쇼츠(의료 장면 등)가 섞여 있음 → 비공개 검토 권함
- 영상 합치기는 **그래픽카드 인코더**로 되고 있음(사용자 확인). 장면 클립 단계가 시간 대부분을 씀

## 3. 지시문을 받았을 때 Claude가 할 일 (중요)

사용자는 프로그램 지시문을 설명 없이 그대로 붙여 넣는다. 지시문 종류별로:

| 지시문 첫 줄 | 할 일 |
|---|---|
| "너는 조회수와 시청 지속률이 높은 유튜브 롱폼 내레이션 작가다" | **대본**. 참고 자료가 없으면 먼저 공식 자료·언론 보도를 검색해 숫자를 확인하고 씀. 글자 수는 `textutil.check_script`와 공백 제외 글자 수로 ±5% 맞추고, 50자 넘는 문장 없게. `## 소제목` 유지 |
| "너는 유튜브 영상 스토리보드 감독이다" | **스토리보드 JSON**. 문장 0~끝을 빈틈없이, `render.MOTIONS`·`pipeline.TRANS_CYCLE` 값만, 사진 용어 금지, 사람 없는 장면은 `no people`. `prompts.fix_storyboard`로 검사 |
| "아래 유튜브 롱폼 대본으로 업로드 정보를 만들어라" | **업로드 정보 JSON**. 쇼츠 구간은 낭독 40~55초(현수 기준 공백 제외 약 4.9자/초, 끊어 읽기로 조금 더 길어짐) |

**출력 규칙**
- 답은 **대본 본문 또는 JSON만**. 앞뒤에 작업 메모를 쓰지 않는다. (사용자가 답 전체를 복사해서, 메모가 대본 첫머리에 섞인 적이 있음)
- 설명이 필요하면 **SendUserFile 캡션**이나 별도 메시지로.
- 숫자는 확인된 것만. 업로드 설명에 참고 자료를 적는다.

## 4. 영상 한 편 만드는 순서 (사용자 기준)

1. **홈**에서 주제를 넣고 채널 성격과 분량(보통 15분)을 정해 시작. 원클릭 자동은 끔
2. **대본**: 지시문 복사 → Claude에 붙여 넣기 → 답을 "직접 붙여넣기" 창에 넣음 → 첫 줄 확인
3. **음성**: Azure 현수. "사람처럼 끊어 읽기(자동)" 켜짐. 어색한 곳은 대본에 `/` 넣고 다시 만들기
4. **화풍**: 웹툰, 등장인물 외형(영어), 장면 길이 20~30초
5. **스토리보드**: 지시문 복사 → Claude 답(JSON) 넣기 → "장면 N개로 나눴어요" 확인
6. **이미지**: 반자동 도우미 → ① 시작 지시문을 Gemini **새 채팅**에 → ② 장면별 프롬프트 복사 → 다운로드되면 자동으로 들어감. "빈 장면 모두 만들기"는 누르지 않기
7. **영상**: 자막 프리셋 고르고 **영상 만들기**. 음성을 바꾸면 영상·쇼츠도 다시 만들어야 함
8. **완성**: 업로드 정보 → 썸네일 **직접 꾸미기**(스타일 8종, 글꼴 8종) → 쇼츠 → MP4 내려받기. 음성이 바뀌면 설명란(챕터 시간)도 새로 복사
9. **유튜브 업로드**
   - 롱폼: 태그는 "자세히 보기", "변경되거나 합성된 콘텐츠"는 **예**, 엔딩 화면은 "동영상 1개 + 구독"
   - 쇼츠: 컴퓨터에서 같은 화면으로 올림(세로·3분 이하면 자동 쇼츠). 썸네일은 못 올리지만 프로그램 쇼츠는 위쪽에 제목이 계속 있어 괜찮음. **관련 동영상**에 롱폼 연결. 롱폼 다음 날 올리기 권함

## 5. 코드 구조

| 파일 | 역할 |
|---|---|
| `studio.py` | 로컬 웹 서버(127.0.0.1, 실행마다 바뀌는 토큰), 프로젝트 저장, 백그라운드 작업, 파일 전송(`/files/_fonts/`는 썸네일 글꼴), 반자동 도우미, 다른 버전이 켜져 있으면 끄고 새로 시작 |
| `pipeline.py` | 단계별 로직: 대본, 음성(문장별 합성·캐시), 스토리보드, 이미지 프롬프트(화풍 보호·사람 판단), 렌더(장면 클립 동시 제작, 바뀐 장면만 다시), 쇼츠, 썸네일, 업로드 정보 |
| `ai.py` | Claude, OpenAI, Gemini, ElevenLabs, Azure(SSML, 끊어 읽기 break), 윈도우 SAPI |
| `prompts.py` | 화풍 19종, 채널 성격, 지시문과 응답 해석(`extract_json`은 앞뒤 설명 글에 괄호가 있어도 JSON을 찾음) |
| `textutil.py` | 문장 나누기, 자막 줄 나누기, 숫자 한국어 읽기, 끊어 읽기(`/` 수동, `auto_phrase` 자동), 대본 점검(AI 메모 섞임 경고) |
| `render.py` | FFmpeg: 켄번즈는 **perspective 필터(흔들림 없음, 바꾸지 말 것)**, xfade 전환, ASS 자막, 배경음 덕킹, -14 LUFS, 그래픽카드 인코더 자동 선택 |
| `ui/index.html` | 화면 전체 (바닐라 JS). 썸네일 편집기는 canvas로 그려 JPG 저장 |
| `build_windows.py` | 윈도우 zip 빌드 (mingw 실행 파일, python.org embeddable, pip 휠, gyan.dev FFmpeg, Google Fonts 글꼴 8종) |

리눅스 개발 실행 예:

```bash
VIDEO_WORKSHOP_HOME=/tmp/vw VIDEO_WORKSHOP_PORT=8765 VIDEO_WORKSHOP_NO_WINDOW=1 python3 studio/studio.py
```

이 명령은 토큰을 출력합니다. API를 부를 때는 `X-Token` 헤더에 그 토큰을 넣습니다. 썸네일 글꼴을 개발 중에 보려면 `studio/ui/fonts/`에 ttf를 넣습니다(저장소에는 넣지 않음, `.gitignore`).

## 7. 알려진 문제와 주의

**사용자 원칙 (꼭 지킬 것)**
- **화면이 흔들리면 안 된다.** 속도 때문에 zoompan으로 되돌리지 않는다.
- 답에 작업 메모를 섞지 않는다 (위 3번).
- 인수인계 문서는 요청할 때만 고친다.

**아직 실제로 확인하지 못한 것**
- Azure 끊어 읽기(SSML break)와 자동 끊어 읽기는 요청 형식까지만 확인. 실제 현수 목소리로 쉬는 길이는 사용자 확인 필요
- 1.3.12 이후 사용자 PC에서 장면 클립 단계가 몇 분 걸리는지 아직 못 받음
- Claude, Gemini 이미지·음성, OpenAI, ElevenLabs 실제 API는 미확인

**알려진 한계**
- 자동 사람 판단(`scene_has_people`)은 영어 낱말 기준이라 가끔 틀릴 수 있음
- 숫자 읽기에서 "2/10은" → "십분의 이은"처럼 조사가 어색할 수 있음
- 음량은 -14 LUFS 고정 (수면용에는 큰 편이지만 사용자가 그대로 쓰기로 함)
- Gemini 무료 앱은 하루 생성 한도가 있음. 그림 30장 이상이면 이틀에 걸칠 수 있음

**사용자가 자주 헷갈린 것**
- 대본·스토리보드를 넣을 때 지시문이 아니라 **답**을 넣어야 함 (1.3.4부터 막아 줌)
- 음성을 바꾸면 영상·쇼츠·설명란(챕터 시간)도 다시 만들어야 함
- 새 zip은 압축을 풀고 새 폴더의 exe를 실행해야 함

## 8. 콘텐츠 원칙 (지금까지 지켜 온 것)

- 대본의 숫자는 **공식 자료나 언론 보도로 확인한 것만** 쓰고, 영상 첫머리에 출처와 한계를 한 문장으로 밝힌다.
- 확인된 자료가 모자라면 분량을 억지로 채우지 않는다.
- 의견·전망은 "~라는 분석도 있어요"처럼 사실과 구분한다.
- 1인칭 시점("저와 우리 부모님")은 쓰되, 실제로 겪은 일처럼 지어내지 않는다 ("제가 계산해 봤어요", "저라면…").
- 건강을 단정하는 공포형 제목, "폭탄" 같은 과장은 피한다. 후킹은 사실(숫자·바뀐 제도)로 만든다.
- 남의 영상·대본을 베끼지 않는다. 업로드 때 "변경되거나 합성된 콘텐츠"는 **예**.
- 구글 계정 여러 개 돌려쓰기, Gemini 앱 자동 조작, 워터마크 제거는 하지 않는다.
